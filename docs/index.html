Prtisan Documentation

Canonical documentation for Prtisan and the agent-train CLI: a local workflow for validating, repairing, and merging GitHub pull request trains with Codex agents in Sandcastle Docker sandboxes.

What Prtisan Does

Prtisan is the project repository for agent-train, a Bun CLI that treats GitHub as the source of truth for open work. It reads pull requests, linked closing issues, branch relationships, issue dependencies, review state, and status checks directly from GitHub.

The CLI runs local Codex agents to review implementation branches against repository standards and issue specs, optionally repair blocking gaps, then merge ready PRs in dependency order.

LoadRead open PR and issue state.
GraphDerive branch and issue dependencies.
ReviewRun Standards and Spec agents.
RepairCommit fixes for blocking gaps.
MergeSquash ready PRs with guards.

Requirements

  • Bun for development and normal CLI execution.
  • Git and a target repository checkout.
  • Docker for Sandcastle agent containers.
  • GitHub CLI 2.94 or newer, authenticated for the target repository.
  • Codex CLI available on the host.
  • A dedicated Codex home under .sandcastle/codex-home, authenticated with codex login.

The workflow is local-first and intended for a trusted workstation or private runner because it mutates branches and uses Codex authentication.

Init

bun run init --cwd /path/to/repo
agent-train init --cwd /path/to/repo

For a GitHub-backed git repository, init detects the repository and default branch through gh repo view, builds the scaffold in a temporary worktree, pushes agent-train/setup, creates or reuses the setup issue, and opens or updates the setup PR.

For a non-git directory, or a git repository not connected to GitHub through gh, init writes the scaffold files directly into the target directory.

Generated Files

  • .sandcastle/agent-train.config.json
  • .sandcastle/Dockerfile
  • .gitignore entries for local runtime state

Configuration

The default config targets origin, keeps runtime state under .sandcastle, and uses bounded concurrency for validation and GitHub API operations. Review and repair models, reasoning effort, Docker image name, CPU budget, extra mounts, and retention policy can be edited in .sandcastle/agent-train.config.json.

If the config still contains OWNER/REPO, update it before running validation or pass --repo OWNER/REPO to commands that support it.

GitHub Issue And PR Conventions

  • Each implementation PR should close or reference its issue.
  • Issue bodies should include agent-readable acceptance criteria.
  • Use GitHub native issue dependencies for blocked-by and blocking relationships.
  • Branch relationships are also part of the dependency graph.
  • Draft PRs stay in the graph, and merge marks each draft PR ready when it reaches that PR.
  • PRs without closing issues receive Standards review only.

Validate

agent-train validate --cwd /path/to/repo --repo OWNER/REPO

validate loads all open pull requests, derives dependencies, runs Standards review for every selected PR, and runs Spec review when a closing issue is present. By default it repairs blocking PR findings when possible and posts a GitHub PR review with a validation marker tied to the current PR head SHA.

It also checks open issues against the target branch, comments with the result, and can create or update an agent-train/repair/issue-N PR when the target branch has blocking gaps and no associated open PR. 

agent-train validate --no-repair

Merge

agent-train merge --cwd /path/to/repo --repo OWNER/REPO

merge reloads open pull requests, processes them in topological order, marks draft PRs ready when it reaches them, and validates or revalidates the current PR when needed, attempts CI and merge-state repair, and stops only when a blocker remains after repair or required human review is missing. Ready PRs are squash-merged only after GitHub is green/mergeable with a head-SHA guard.

After each squash merge, affected descendants are restacked and validation is rerun. Multi-blocker PRs may use synthetic base branches so GitHub's single-base PR model can represent a DAG.

TUI

agent-train tui --cwd /path/to/repo --repo OWNER/REPO

tui opens an interactive terminal dashboard for operating the same validate and merge workflows. It shows the configured repository and target branch, runtime readiness diagnostics, open PR train layers, validation state, draft status, blockers, and recent workflow events.

Actions include refreshing the train, running preflight, validating, merging, and quitting. Validate and merge require explicit confirmation because validation can repair and push branches or post GitHub reviews/comments, and merge can squash PRs.

The TUI requires an interactive terminal. In CI, piped output, or other non-TTY environments, use agent-train validate or agent-train merge directly.

Codex And Sandcastle Setup

mkdir -p .sandcastle/codex-home
CODEX_HOME="$PWD/.sandcastle/codex-home" codex login

agent-train validate and agent-train merge build the configured Sandcastle Docker image from .sandcastle/Dockerfile when it is missing.

Do not mount your full personal ~/.codex into agent containers. The dedicated Codex home keeps unrelated auth, logs, and sessions out of the sandbox.

Troubleshooting

  • Missing agent train config: run agent-train init, fix the config, or pass --repo OWNER/REPO.
  • Issue dependency errors: upgrade GitHub CLI and check repository permissions.
  • Missing CODEX_HOME: create .sandcastle/codex-home and authenticate it.
  • Docker image build failed: fix .sandcastle/Dockerfile, then rerun the command or build it manually with docker build -t sandcastle:agent-train -f .sandcastle/Dockerfile ..
  • Setup branch looks stale: rerun agent-train init.
  • agent-train tui refuses to start: run it from an interactive terminal, or use agent-train validate or agent-train merge for non-interactive automation.
